## Принципы архитектуры (уже отражены в README п.1)
- AI-агент там, где нужно суждение; цифры считает обычный код
- Два контура: фоновый (сбор и расшифровка заранее) и запросный (читает готовые данные)
- На старте система read-only: только читает amoCRM и телефонию, ничего не меняет
- STT и LLM локальные или российские (152-ФЗ, ПДн в записях звонков)
- Калибровка: РОП вручную оценивает 20–30 звонков, сверяем с моделью
- Каждый вывод отчёта — со ссылкой на ID сделки/звонка + цитата с таймкодом
- Оркестрация: сначала Python-пайплайн; LangGraph — при появлении свободных запросов и ветвлений

## Телефония
- Примеры: UIS, Гравител, Asterisk, Mango Office; запасной путь — webhook
- Звонки в amoCRM часто лежат как примечания call_in/call_out со ссылкой на запись
- Звонок часто привязан к контакту, а не к сделке — связывать через контакт
- Аудио сохранять к себе сразу: внешние ссылки могут перестать работать

## Риски (отражены в README п.2)
1. Грязные данные CRM → блок «качество данных» в отчёте, выводов при малом объёме нет
2. Ошибки STT и галлюцинации LLM → фикс-схема JSON, цитата-доказательство, калибровка
3. 152-ФЗ и безопасность → локальные модели, маскирование ФИО/телефонов, токен в секретах, защита от prompt injection

## Лимиты amoCRM
- 7 запросов/с на интеграцию, до 50 на аккаунт; превышение → 429, повторы → 403 и блок
- Синхронизация постепенная, не полной выгрузкой

## Обработка звонков (MapReduce)
- Map (фон): звонок расшифрован и оценён по чек-листу сразу → карточка JSON
- Reduce (запрос): агрегация готовых карточек SQL → ответ за секунды

## Чек-лист оценки звонка (лизинг)
- Потребности: какой авто (новое/пробег), бюджет, взнос (10%/без)
- Возражения: дорого, не тот авто, срок, проверка документов
- Перебивания, стоп-слова, тональность
- Причина отказа из фиксированного списка
- Корректность расчёта ежемесячного платежа и объяснения SLA
